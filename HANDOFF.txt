8. GOTCHAS / HARD-WON LESSONS
----------------------------------------------------------------
- *** EVERY DEPLOY RUNS `prisma db push --accept-data-loss`. *** That
  flag will drop columns and data to make the database match the
  schema. Never push a schema change here casually, and never push a
  half-finished schema. This is also why a multi-file change must be
  ONE deploy, not several.
- To make a multi-file change one deploy: on the FIRST upload choose
  'Create a new branch for this commit and start a pull request',
  name the branch, upload the remaining files to
  /upload/<new-branch>/<dir> (those commits do not trigger the deploy
  workflow), then compare -> Create pull request -> Merge. One deploy
  for the whole change.
- Branch names WITH SLASHES work in the upload URL. A path segment
  with parentheses must be percent-encoded, e.g.
  src/app/%28dashboard%29/settings
- COLLECTING SESSION is PER COMPUTER, never per account. localStorage
  key `social_collecting`, card in Settings. Default ON. Staleness is
  still shown to viewers - only the instruction changes.
- Writes go through the GitHub web UI in Chrome; `git push` is
  proxy-refused and the API 403s on write. Upload ONE file per call
  (multi-file calls get refused), retry once on a random refusal, and
  verify every commit by reading raw.githubusercontent.com.
